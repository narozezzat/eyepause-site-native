# AGENTS.md

Operating manual for AI coding agents (Claude Code, Codex, Cursor, etc.) in this repo. Read it fully before changing code. These rules override generic defaults.

## 1. Project

eyepause-site-native: the download site for EyePause, the macOS menu bar break reminder, in the "Menu Bar Native" design.

- Next.js 16 (App Router) with static export (`output: "export"`), React 19, TypeScript (strict), Tailwind CSS 4, shadcn/ui on Radix primitives.
- Deployed to GitHub Pages by `.github/workflows/pages.yml`. There is no server: no API routes, server actions, cookies or runtime env.
- Light, dark and system themes through `next-themes` with `attribute="data-theme"`. The `dark:` variant is defined in `globals.css` to follow `[data-theme=dark]`.

## 2. Commands

```bash
npm run dev         # http://localhost:3000
npm run lint        # eslint
npm run typecheck   # next typegen && tsc --noEmit
npm test            # vitest (tests/**/*.test.ts)
npm run build       # static site in out/
```

## 3. Layout

```
src/app/              layout, page, loading, not-found, globals.css (tokens + component CSS)
src/components/ui/    shadcn/ui primitives and small shared UI (button, alert, dropdown-menu, …)
src/components/       brand/ download/ layout/ sections/ theme/ (one folder per area)
src/config/           platforms and site config (what exists, not how it looks)
src/data/release.json release data, generated by scripts/fetch-release.mjs
src/hooks/            client hooks
src/lib/              pure logic (releases, platform detection, theme, format) and utils.ts (cn)
tests/                vitest unit tests for src/lib
```

Dependency direction: `app -> components -> hooks/lib/config`. `src/lib` is pure TypeScript: no React, no DOM.

## 4. Engineering standards

Work at Staff-engineer level: clean, scalable, maintainable code that matches the existing conventions.

- **TypeScript:** strict mode stays on. No `any`, no `as any`, no `@ts-ignore`. Prefer precise types, discriminated unions and `satisfies`; narrow `unknown` with type guards.
- **Reuse first:** search for an existing component, hook or util before writing one. Never duplicate logic; extract it to `src/lib` or a hook when two places need it.
- **Components:** small and focused, one responsibility each. Server components by default; add `"use client"` only where state, effects or browser APIs are needed.
- **shadcn/ui:** prefer the primitives in `src/components/ui` (and new ones via `npx shadcn@latest add <name>`) over hand-rolled widgets. Generated files are owned code: adapt their classes to this project's tokens, keep their structure and conventions (`cn`, `cva`, `data-slot`, Radix parts). Use `cn` from `@/lib/utils` for class composition.
- **Dependencies:** none without a clear need that existing code or the platform can't meet. Ask before adding one.
- **Conventions:** follow the patterns already in the file and folder you touch: naming, import style (`@/` alias), comment density. No drive-by refactors or reformatting.

## 5. Styling and design

- **No redesign unless asked.** Preserve layout, spacing, typography, colors, motion and responsive behavior exactly. A refactor must render pixel-identical.
- **Tokens only:** colors come from the CSS variables and `@theme` tokens in `globals.css` (`--bg`, `--fg`, `--surface`, `--accent`, `--border`, …, and Tailwind classes like `bg-surface`, `text-fg-muted`). No hex, rgb or arbitrary color values in components.
- **Both themes:** every change must look right in light and dark (and system). Define a new color as a token with values for both themes, never inside one theme only.
- **rem over px:** spacing, typography, sizing and radius use rem (16px root: `13px` = `0.8125rem`). px is allowed only for borders and 1px hairlines, outlines and outline offsets, shadows, transforms, and `@media` / `@container` breakpoints.
- **Responsive:** check 375, 768 and 1440 widths. No horizontal page scroll.
- **Accessibility:** semantic HTML first (`button`, `a`, `nav`, `section`, headings in order), ARIA only where semantics fall short. Every interactive control has an accessible name and a visible `:focus-visible` state. Respect `prefers-reduced-motion`. Keep contrast at WCAG AA in both themes.
- Use `focus({ preventScroll: true })` when moving focus programmatically: the header is sticky and scrolling is smooth, so a plain `focus()` scrolls the page.

## 6. Changing existing code

- Before changing a component, find all its usages (`grep` the import) and keep them working.
- Minimize breaking changes: keep public props and exports stable, or update every caller in the same change.
- Bugs: find the root cause before fixing. Don't patch symptoms.

## 7. Project rules

- `src/data/release.json` is generated by `npm run fetch-release`. Never hand-edit it or commit a locally rewritten copy.
- Never print, log or commit `EYEPAUSE_RELEASES_TOKEN` or any other secret.
- The site has no GitHub, source-code or open-source links.
- Don't commit `out/`, `.next/`, `node_modules/` or `public/downloads/`.

## 8. Verification (definition of done)

After any significant change run, and paste real output:

```bash
npm run lint && npm run typecheck && npm test && npm run build
```

- All four pass with no new warnings.
- New logic in `src/lib` has tests.
- UI changes are checked in a browser at 375 / 768 / 1440, light and dark, keyboard-only, with no visual regressions.
- Never mark work done without verifying it. If something couldn't be verified, say so.

## 9. Git

- Conventional Commits (`feat(scope): …`, `fix(scope): …`, `refactor: …`, `chore: …`). Imperative subject, 72 chars max, body explains why.
- Don't commit, push or open PRs unless asked.
